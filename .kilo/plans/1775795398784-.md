# OnlyFans Media Downloader - Chrome Extension Plan

## Overview
Build a Manifest V3 Chrome extension that adds a download button to OnlyFans creator profile pages, allowing users to download all images and videos from feed posts, organized by creator name, with duplicate detection.

## Architecture

### Extension Components
1. **manifest.json** - Manifest V3 config, permissions, content script registration
2. **content.js** - Injected into onlyfans.com pages; adds download UI, orchestrates downloads
3. **background.js** - Service worker; handles Chrome downloads API calls, auth header interception
4. **styles.css** - Styling for the injected download button and progress bar
5. **popup.html/popup.js** - Minimal popup with link to open current creator page (optional, lightweight)

### Key Permissions
- `activeTab`, `downloads` - for triggering downloads
- `storage` - for tracking downloaded files (duplicate skip)
- `webRequest` / `declarativeNetRequest` - to capture auth headers (sign, user-agent, user-id, x-bc) from existing OF API requests
- Host permission: `https://onlyfans.com/*`

## Implementation Steps

### 1. Project Setup
- Create extension directory structure
- Write `manifest.json` with Manifest V3 configuration
- Set up content script matching `https://onlyfans.com/*`

### 2. Auth Header Capture (background.js)
- OnlyFans API requires specific headers: `sign`, `time`, `app-token`, `user-id`, `x-bc`
- Use `chrome.webRequest.onBeforeSendHeaders` listener to capture these headers from the browser's own API requests to `https://onlyfans.com/api2/v2/*`
- Store captured headers in memory for reuse by the content script
- Provide a messaging API (`chrome.runtime.sendMessage`) so the content script can request current auth headers

### 3. Content Script - UI Injection (content.js)
- Detect when user is on a creator's profile page (URL pattern: `onlyfans.com/<username>`)
- Extract creator username from the URL
- Inject a "Download All Media" button near the creator's profile header
- Inject a progress container (progress bar + status text + file counter)
- Add start/stop/pause controls

### 4. Content Script - API Pagination & Media Extraction
- Use the captured auth headers to call OF's internal API:
  - `GET /api2/v2/users/<username>` - resolve username to user ID
  - `GET /api2/v2/users/<user_id>/posts` - paginate through all posts (query params: `limit=50`, `offset` or `beforePublishTime` cursor)
- For each post, extract media items from the `media` array in the response
- Filter for `type: "photo"` and `type: "video"` 
- Collect `full` URL for images, `source.url` for videos (highest quality)
- Handle pagination until no more posts are returned

### 5. Download Manager
- Send download requests to background.js via messaging
- Background.js uses `chrome.downloads.download()` with:
  - `filename`: `OnlyFans/<creator_name>/<media_id>_<original_filename>`
  - `conflictAction`: `uniquify`
- Rate-limit downloads (2-3 concurrent) to avoid overwhelming the browser
- Track progress and report back to content script for UI updates

### 6. Duplicate Detection
- Before downloading, check `chrome.storage.local` for previously downloaded media IDs
- Key structure: `{ "downloaded_<creator>": { "<media_id>": timestamp } }`
- After successful download, record the media ID
- Show skip count in progress UI

### 7. Progress UI
- Show: `Downloading: 45/230 (12 skipped) - video_abc123.mp4`
- Progress bar with percentage
- Estimated time remaining based on average download speed
- "Complete" state with summary when finished

## Technical Notes
- **No external dependencies** - pure vanilla JS for simplicity and security
- **Manifest V3** - uses service worker instead of background page
- **Rate limiting** - 500ms delay between API calls to avoid OF rate limits
- **Error handling** - retry failed downloads up to 3 times with exponential backoff
- **Storage limits** - chrome.storage.local has 10MB limit; sufficient for tracking IDs (not media)
- Icons will be simple placeholder SVG-based PNGs

~400-500 lines of code across all files. Focused implementation, no bloat.
